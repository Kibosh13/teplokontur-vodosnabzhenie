# GVS-Group

Сайт компании по монтажу отопления и водоснабжения, опубликованный на
[gvs-group.ru](https://gvs-group.ru/). На Beget сайт работает через PHP с
кастомной панелью управления. GitHub Pages остаётся статической демоверсией.

## Структура

- `site/` — исходные HTML, CSS, JavaScript, шрифты и изображения;
- `server/admin/` — интерфейс и API панели управления;
- `server/cms/` — движок, схема полей, исходное содержание и шаблоны страниц;
- `scripts/build-cms.php` — создание редактируемых шаблонов из `site/`;
- `scripts/prepare-production.php` — сборка пакета для PHP-хостинга;
- `scripts/deploy-cms.py` — установка/обновление CMS через FTPS;
- `scripts/test-cms.py` — полный интеграционный тест на изолированном localhost;
- `scripts/check-cms-production.py` — проверка публикации на боевом домене;
- `scripts/prepare-pages.mjs` — подготовка безопасной демонстрации для Pages.

## Панель управления

Адрес: [gvs-group.ru/admin/](https://gvs-group.ru/admin/).
Пароль не хранится в репозитории. При первом входе нужно заменить выданный
временный пароль на собственный. Раздел «Безопасность» позволяет менять его
позже; остальные сеансы при этом завершаются.

1. В «Страницах сайта» выбрать страницу и нужный блок. Вкладки разделяют
   тексты, фотографии и SEO. Поиск находит поле по текущему содержимому.
2. Телефон, почта, подпись, логотипы и график редактируются в «Компании и
   контактах» — общие данные автоматически используются на всех страницах.
3. Загрузить фото в медиатеку или прямо через «Заменить фото». Принимаются
   JPG, PNG и WebP до 8 МБ и 20 мегапикселей. Изображения безопасно
   пересохраняются в WebP, длинная сторона ограничивается 2560 пикселями.
4. Нажать «Сохранить»: это только черновик, посетители ещё видят старый сайт.
5. Открыть «Предпросмотр» и проверить компьютерную/мобильную версию.
6. Нажать «Опубликовать» и подтвердить. Предыдущая версия сохранится в
   «Истории публикаций», откуда можно восстановить всё содержание.

Редактируются существующие блоки всех шести страниц, включая цены, подписи
к фото, формы и меню. Новые страницы или изменение структуры макета требуют
правки исходников. Панель не является CRM и не добавляет отправку заявок:
нынешние клиентские формы сами по себе не отправляют письма.

В SEO доступны title, description, canonical, изображение для ссылки и
переключатель индексации каждой страницы. Боевые страницы по умолчанию
открыты для поиска. `robots.txt` закрывает только `/admin/` и `/.cms/`;
`sitemap.xml` автоматически содержит опубликованные индексируемые страницы.
Админка и черновики всегда имеют `noindex` и не попадают в карту сайта.

## Хранение данных и безопасность

На хостинге состояние, хеш пароля, сеансы и история находятся в
`public_html/.cms/private/`. Каталог защищён от HTTP-доступа и не включается
в Git или пакеты обновлений. Пользовательские фотографии находятся в
`public_html/assets/uploads/` и также не перезаписываются обновлением кода.
Для полного резервного копирования нужны **оба каталога**, а не только Git.
Скачивать их следует по FTPS; резервные копии с хешами пароля и сеансами
нельзя публиковать.

Сеансы защищены HTTPS, HttpOnly и SameSite; записи требуют CSRF-токен.
Неудачные входы ограничены по IP, тексты экранируются, загрузка исполняемых
файлов и SVG запрещена. Сохранение атомарное с блокировкой и проверкой
версии: параллельные вкладки не должны молча перетирать изменения.

## Локальная проверка и установка

Нужны PHP 8.2+ с DOM, mbstring, GD и fileinfo; Python 3 для FTPS/проверок.
База данных, npm-зависимости и сервер Node.js не требуются.

```bash
php scripts/build-cms.php
php scripts/prepare-production.php /absolute/empty/output-directory
php -S 127.0.0.1:4174 -t /absolute/empty/output-directory scripts/dev-router.php
```

Для изолированного теста создать временную учётную запись в
`/absolute/empty/output-directory/.cms/private/account.json`: поля
`username`, `hash` (результат `password_hash`), `generation` (случайная
строка), `mustChange` (false только в тестовой среде). Создать закрытые
каталоги `private/sessions` и `private/versions`. Не добавлять эти данные
в исходники. Затем выполнить:

```bash
python3 scripts/test-cms.py http://127.0.0.1:4174
```

Установка/обновление боевой CMS:

```bash
python3 scripts/deploy-cms.py /absolute/empty/output-directory
python3 scripts/check-cms-production.py
```

Учётные данные вводятся через скрытый stdin, не аргументы команд. Для
deploy нужен JSON с `password` хостинга и, только при первоначальной
установке, объектом `account` указанной структуры. В реальном аккаунте
использовать `mustChange: true`. Проверка production сначала требует
пустого клиентского черновика и уже заменённого пароля; тестовый текст
сохраняется только в черновик и удаляется **до** публикации. Проверка
публикует исходное неизменённое содержание.

Деплой отправляет только CMS, PHP-точки входа и правила доступа. Старые
статические robots/sitemap переносит в закрытые резервные файлы, чтобы
nginx Beget не перехватывал их у PHP. Статические HTML/изображения из `site/`
уже размещены отдельно. После изменения макета нужно пересоздать шаблоны;
после изменения статических CSS/JS эти конкретные файлы необходимо также
обновить на хостинге. Стабильные идентификаторы полей важны для сохранения
пользовательских текстов: при изменении структуры генератора нужна миграция.

## GitHub Pages

Исходники — в `main`, статическая демонстрация — в `gh-pages`.
Демоверсия не включает PHP, учётную запись, медиатеку и редактор.
Скрипт адаптирует ссылки под путь репозитория, добавляет `noindex`, закрывает
обход в `robots.txt` и помечает формы как демонстрационные.

```bash
node scripts/prepare-pages.mjs .pages
```
